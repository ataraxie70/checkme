# A0.6 — CI, lockfile and main governance

## Decision

CheckMe! treats reproducible dependency installation and protected integration as architecture-level requirements.

## Current baseline

- Node runtime is pinned to the 24.18 line.
- `npm ci` is the canonical CI installation command.
- `npm ci --dry-run` is an explicit lockfile verification gate.
- CI uses read-only repository permissions.
- CI runs with concurrency cancellation to avoid stale runs consuming resources.
- `main` must be protected by repository rules; the exact GitHub rules are documented in `BRANCH_PROTECTION.md`.

## Lockfile blocker

The current repository lockfile was originally created as a workspace scaffold and does not yet contain a complete dependency graph for the current `package.json` files. It must be regenerated by npm before A0.6 can be marked complete.

This is intentionally not solved by hand-editing `package-lock.json`.

## Exit criteria

A0.6 is complete only when all of the following are true:

- `npm ci` succeeds from a clean checkout;
- `npm ci --dry-run` succeeds;
- `make check` succeeds;
- GitHub `Foundation checks` is green;
- `main` protection requires the Foundation checks status;
- direct force-push and branch deletion are blocked.
